## Findings considered and rejected

- **CCXT loads full market list per search** (performance): ccxt's market list
  changes infrequently. Caching it in-memory with a TTL would help, but CEX
  search is already fast enough (<1s) and not on the hot path (users search
  CEX pairs rarely compared to token searches). Not worth the complexity yet.
- **Worker single-process gather — one loop crash kills all three**
  (reliability): True but low-impact for a hobby bot. Docker's `restart:
  unless-stopped` provides adequate recovery. Adding a supervisor adds
  complexity disproportionate to the risk.
- **No webhook secret validation in middleware**: aiogram's
  `SimpleRequestHandler` already validates `X-Telegram-Bot-Api-Secret-Token`
  when `secret_token` is set. Verified — `main.py:44` passes it. Not a finding.
- **Missing transaction around multi-table asset upsert** (correctness):
  SQLAlchemy's `insert(...).on_conflict_do_update(...)` is atomic per
  statement. The link upserts in the loop are independent idempotent
  operations — a partial failure leaves the asset with fewer links, which is
  self-healing on the next refresh. Low risk, not worth a plan.
- **Magic strings in alert type checks**: The pattern `alert.type ==
  AlertType.PERCENT_CHANGE.value` is verbose but unambiguous. Refactoring to
  use enum instances stored on the model would require a migration. Defer.
- **Duplicate HTTP retry logic across providers**: True, but the duplication is
  two near-identical `_get_json` methods. Extracting to a shared helper is
  a refactor, not a bug fix. Plan 003 fixes the missing retry on DexScreener;
  a dedup refactor can follow later.
